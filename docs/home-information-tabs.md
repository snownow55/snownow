# ホームの情報タブ（先行無料公開）

- 朝のコンディションとゲレンデの今の2タブを維持する。登録エリアを優先した地域別表示、検索、地域選択、地域内の並び替えは共通のURL状態を使用する。
- ゲレンデの今はログイン状態によらず無料閲覧。既存の `loadResortPostSummaries` と `ResortLiveCard` で、施設ごとの最新投稿本文・雪質・降雪・荒れ具合・混雑・日本時間の投稿日時を表示する。投稿者IDやAuth情報は取得しない。
- 投稿なし・読込中・取得失敗を区別する。失敗時や地域変更時に、前の地域の本文を表示しない。最新投稿順の日時は同じ読取結果を使い、日時だけの二重取得はしない。
- 詳細リンクはタブ・地域・検索・並び順を保持する。投稿には従来どおりメール確認済みアカウントでのログインが必要。API・RLS・60分制限は変更しない。
- 朝の公式情報は既存の当日判定・掲載許可による公開ビューを使う。投稿から公式値を補完せず、未取得を0に置換しない。和寒東山は朝だけ除外する。
- `/access` は無料閲覧と投稿条件の説明。現在の画面に課金・チケット・無料体験の開始案内は出さない。
- 将来用の `LockedResortCard` と有料案内原案 `components/future-access-guide.tsx` は保持するが、今回の公開画面では使用しない。課金・チケット・閲覧権を実装済みとはしない。

## 将来の有料閲覧

有料化時は詳細・API・DB読取を含むサーバー側の認可が必要。現在は投稿情報を公開する無料仕様であり、固定ロックカードに切り替えるだけでは保護にならない。認可前の本文送信や共有キャッシュによる混在を防ぐ設計を行う。

## 朝の公式情報を取得するジョブ

`npm run collect:official` は、指定した情報源を順に処理して終了する。実行にはジョブ専用の `OFFICIAL_SUPABASE_URL` と `OFFICIAL_SUPABASE_SERVICE_KEY`、および `OFFICIAL_APPROVED_SOURCES` が必要。最後の変数は情報源IDから承認済みHTTPS URLへのJSONマップ（合成例 `{"1":"https://fixture.invalid/snow"}`）。サービスキーは実行環境の秘密変数として管理する。

施設ごとの明示的な承認後に、対象DBへのマイグレーション適用と情報源登録を行う。取得許可・掲載許可・確認日時・適用範囲を記録し、URLと `adapter_key` を設定する。取得直前に指定URLとDB上のURLが一致し、取得・掲載がそれぞれ `allowed` で有効な場合だけ通信する。保存時にDBで再照合し、通信中に取消しやURL変更があった結果は保存しない。公開ビューも両方の許可を確認する。実施設の登録と定期実行の設定は別途行う。

`json-v1` は次の形式のHTTPS JSONフィードを処理する。情報源の実際の形式が異なる場合は、許可済みの実データ形式に合わせて専用アダプターを追加する。

```json
{
  "status": "success",
  "observation_date": "2026-11-21",
  "observed_at": "2026-11-21T07:00:00+09:00",
  "published_at": "2026-11-21T08:30:00+09:00",
  "location_kind": "summit",
  "location_name": "山頂",
  "new_snow": { "value": 135, "unit": "mm" },
  "snowfall_period": "昨晩から",
  "snow_depth": { "value": 125, "unit": "cm" },
  "temperature": { "value": -5, "unit": "C" }
}
```

日付は日本時間。観測・発表時刻はオフセット付き日時で、省略できる。降雪・積雪は `mm`・`cm`・`m`、気温は `C`・`F` に対応する。新雪の発表がない場合は `snowfall_24h` を同じ単位形式で使用できる。 `snow_depth` は積雪欄だけに使用する。 `missing`・`closed`・古い観測・取得失敗には測定値を保存しない。

取得は1情報源あたり8秒、応答本文は256 KiBまで。リダイレクトは拒否する。実行結果はIDと結果コードだけを出力する。取得・DBエラーがあれば終了コード1となり、他の指定情報源の処理は続ける。
