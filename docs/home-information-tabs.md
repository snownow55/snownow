# ホームの情報タブ（開発版）

- 朝の各カードの導線は「今のゲレンデコンディションを見る」の1つのみ。既存の内部名 `name` による詳細URLを維持し、詳細ページからの投稿導線は変更しない。「ゲレンデの今」は従来の詳細・投稿ボタンを維持する。
- 初期表示は「朝のコンディション」。公式取得処理は未実装で、新雪量・積雪量・発表日時はすべて「未取得」。ユーザー投稿を公式値に流用しない。
- 「ゲレンデの今」は全員に固定プレースホルダーのロックカードを表示する。ログイン状態やURLで解除する仕組みは設けない。
- `LockedResortCard` が受け取るのはスキー場マスタと公開日時メタデータのみ。投稿の有無・相対時刻・日本時間の投稿日時を無料表示する。実投稿の本文・雪質・混雑などを取得・描画してからぼかす方式ではない。読み込み中・取得失敗は「投稿なし」と区別する。
- 従来の実投稿カードは `ResortLiveCard` に保持。日時、現地メモ、位置、2行省略・展開の既存 `ResortMemo`、詳細・投稿リンクを再利用できる。現時点のホームからは使用しない。
- ホームの検索・地域選択・並び順はタブ間で共有する。地域変更でもタブと並び順を維持。最新投稿順は、公式発表日時とは別のユーザー投稿日時による並び順と明記する。
- スマホでは現在の地域名が表示されるネイティブの選択欄で9地域を切り替える。768px以上では従来の地域ボタンを表示する。キャッチコピーと説明文を除き、ブランドの直下にタブを配置。閲覧制度の説明と案内リンクは「ゲレンデの今」の上部に1回だけ表示し、カードはコンパクトな固定ロック表示とする。
- 並び替え用の読み取りは `created_at` だけを取得する。地域ごとに最大13リクエスト（各スキー場1件）、別途マスタ2リクエスト。従来の投稿本文・件数取得より転送量とCOUNT処理を減らすが、地域変更時のリクエスト数は残る。検索やタブ切り替えでは追加取得しない。
- 日時取得に1件でも失敗した場合は部分的な最新順を出さず、五十音順とエラー表示にする。公式未取得カード・ロックカード・投稿導線は使用可能。
- `/access` は制度の説明のみ。チケット付与・消費・課金・無料体験開始・閲覧権判定は実装していない。

## 将来の閲覧制御について

これは有料情報の保護機能ではない。既存の詳細ページ、公開ビュー、API、RLS、認証には変更を加えておらず、既存の投稿は引き続き公開範囲のまま。

有料閲覧を公開する前に、詳細ページ・一覧取得・直接API/DB読み取りを含む全経路でサーバー側の閲覧権確認を設計・検証する必要がある。認可前は実投稿をクライアントやRSCペイロードに送らず、認可済みの応答だけを `ResortLiveCard` に渡す。共有キャッシュによる混在も防ぐ。単にカードを切り替えるフラグを追加して有料保護済みとしない。

## 検証方針

実DBを使わず、ローカルSupabaseモックで59件・9地域、タブ、検索、並び順、リンク、ログイン復帰、投稿後の遷移を確認。ホームの投稿読み取りが日時だけであることと、ロックカードのDOM・応答に本文がないことを検証する。保持した実投稿カードは本番に解除用テストルートを設けず、テストプロセス内で描画を検証する。
