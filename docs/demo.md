# スキー場関係者向けデモ

開発ブランチのアプリで `/demo` を開きます。Supabase設定・ログイン・課金は不要です。詳細も `/demo/resort/[内部名]` に直接アクセスできます。デモ内のリンクはこの名前空間だけを使い、通常の詳細・投稿・認証・課金へ誘導しません。

## マスターとサンプル

名称・地域分類は、登録時にレビューした `docs/resort-master-review/59-resorts-review.csv` を参照します。地域名と期待件数は同フォルダの `02-dev-master-change-draft.sql` の `_expected_regions` 定義から読み取ります。これはファイルの読み取りのみで、SQLは実行しません。登録済みの北海道9エリア・59スキー場を表示対象とし、初期選択は旭川・富良野です。実DBの接続・照会は行いません。DBマスター変更は自動同期されないため、登録資料との整合を保ってください。名称・表示名をデモ用に別途列挙していません。

`lib/demo/data.ts` が旭川・富良野の10スキー場だけに各3件、合計30件の固定サンプルを生成します。デモ想定日は2026年2月14日、日本時間9:00・11:30・14:00〜14:20です。最新順での比較を体験できるよう、午後の時刻に差を設けています。同時刻は既存の読み仮名による五十音順です。現在時刻・乱数・実際の投稿は使用しません。シナリオは登録順で割り当てた架空の変化で、実際の地形やスキー場の特性を表しません。個人情報・DB投稿ID・ユーザーIDはありません。

「朝のコンディション」は公式連携の表示枠で、1行目「新雪量｜雪質」、2行目「積雪量｜気温」の2列×2行で、4項目は「未取得」のままです。発表日時は4項目の下に小さく「発表日時：未取得」と表示します。通常アプリ・デモのカードと詳細で共通部品を使い、詳細では投稿履歴とは別の公式情報枠として表示します。架空のユーザー投稿から公式情報を推測しません。サンプルは「ゲレンデの今」とデモ詳細で閲覧できます。詳細は朝から午後の昇順で3件を表示し、一覧への復帰リンクには許可されたタブ・エリア・検索語・並び順だけを含めます。エリア未指定の従来URLは引き続き旭川・富良野を開きます。直接開いた他地域の詳細からは、その地域の一覧へ戻ります。

エリア選択では正式な9地域名と、集約表示用の「北海道全域」を選択できます。`region=all` は59件をまとめて表示します。スマホは選択欄、PCは地域ボタンです。サンプル生成は `DEMO_REGION_CODE`（旭川・富良野）に限定し、他地域の49施設では「デモ投稿なし」を表示します。施設名の掲載は提携・公式情報連携の完了を意味しないことを全画面で明示します。

最新投稿順はサンプルのある10件を先頭にし、同時刻・投稿なし同士は五十音順です。サンプルがない詳細には架空の時刻・雪質・コメントを表示しません。「デモ投稿なし」は実際の投稿数や営業状況を示すものではありません。

## 分離と検証

通常の `AuthProvider`・投稿API・RLS・認証判定は変更していません。通常画面だけをURLに影響しない `app/(app)` ルートグループにまとめ、同レイアウトで既存の認証プロバイダーを維持しています。デモには認証プロバイダーを配置せず、Proxyのマッチ対象から `/demo` とその配下だけを除外しています。通常画面の認証・セッション更新は維持します。デモには書き込みUI・API呼出し・Supabaseクライアントがありません。これは通常画面の閲覧制御や有料保護を実装する変更ではありません。

Vercelのサーバーバンドルにマスター資料を含めるため、`next.config.ts` にデモ用のファイルトレース設定を追加しています。外部データ取得処理はありません。ルートは検索エンジンのインデックス対象外です。

検証コマンド：

- `npm test`
- `npm run test:e2e`（ローカルモック。デモではSupabase・認証・API通信とGET以外のブラウザリクエストを禁止）
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `npm run test:e2e:missing`（Supabase設定を空にしてビルドした後、実行。ビルド済みの全域一覧59件、旭川・富良野の全詳細と投稿なしの詳細を直接開いて確認）

本番へのデプロイやDBへの操作は必要ありません。
